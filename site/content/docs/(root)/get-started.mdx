This guide covers what you need to add **time2code/ui** components to a React app: the CLI, the color tokens and the root layout that Base UI expects.

## Prerequisites

The components are built with [Tailwind CSS v4](https://tailwindcss.com). You need a React project with Tailwind CSS v4 set up. The examples on this page use the Next.js App Router.

## New Project

To start a Next.js app that is ready for the components, run:

<PackageManagerTabs
  className="not-typeset full-width"
  command="npx time2code create my-app"
/>

The template sets up Tailwind CSS v4, Biome, the [color tokens](/docs/styling), the fonts and the root layout described below, so you can skip to [adding components](#add-components).

## Existing Project

Setting up an existing project takes three steps: add the color tokens, set up the root layout, then add components.

### Add the Color Tokens

The components are styled with time2code/ui's own color tokens, not the shadcn/ui ones. Neither CLI adds them for you, so copy them into your global stylesheet first. You'll find the full stylesheet under [Styling](/docs/styling#installation).

### Set Up the Root Layout

Base UI renders popups such as Dialog, Popover, Menu and Select in a portal at the end of `<body>`. Two classes in your root layout keep them above the page content:

- **`isolate` on the app's root element** creates a separate stacking context for the page. Portaled popups render outside of it, so they always appear above the page content, without z-index conflicts.
- **`relative` on `<body>`** makes popup backdrops cover the visible viewport in iOS Safari 26 and later, even after the page has scrolled.

This is the root layout of this site, reduced to what the components need:

```tsx title="app/layout.tsx"
import { Geist, Geist_Mono } from "next/font/google";

import { ThemeProvider } from "@/components/theme-provider";
import { ToastProvider } from "@/components/ui/toast";

import "./globals.css";

const geistSans = Geist({
  display: "swap",
  subsets: ["latin"],
  variable: "--font-geist-sans",
});

const geistMono = Geist_Mono({
  display: "swap",
  subsets: ["latin"],
  variable: "--font-geist-mono",
});

export default function RootLayout({ children }: LayoutProps<"/">) {
  return (
    <html
      className={`${geistSans.variable} ${geistMono.variable}`}
      lang="en"
      suppressHydrationWarning
    >
      <body className="relative bg-background font-sans text-foreground antialiased">
        <div className="relative isolate flex min-h-svh flex-col">
          <ThemeProvider>
            <ToastProvider>{children}</ToastProvider>
          </ThemeProvider>
        </div>
      </body>
    </html>
  );
}
```

The rest of the layout is optional:

- **`ThemeProvider`** switches between light and dark mode by setting the `dark` class on `<html>`, which the [color tokens](/docs/styling#dark-mode) respond to. `suppressHydrationWarning` is needed because the class is set before React hydrates.
- **`ToastProvider`** is only needed if you use [Toast](/docs/ui/toast). Add `AnchoredToastProvider` inside it if you use anchored toasts.
- **The font variables** connect `next/font` to the `font-sans` and `font-mono` utilities. See [Fonts](/docs/styling#fonts).

`ThemeProvider` is a small wrapper around [next-themes](https://github.com/pacocoursey/next-themes). Install `next-themes`, then add this file:

```tsx title="components/theme-provider.tsx"
"use client";

import { ThemeProvider as NextThemesProvider } from "next-themes";

export function ThemeProvider({
  children,
  ...props
}: React.ComponentProps<typeof NextThemesProvider>) {
  return (
    <NextThemesProvider
      attribute="class"
      defaultTheme="system"
      disableTransitionOnChange
      enableSystem
      {...props}
    >
      {children}
    </NextThemesProvider>
  );
}
```

## Add Components

You can add components with the `time2code` CLI, with the shadcn CLI or by copying the files. All three work for UI components, charts, marketing components, hooks and blocks.

### With the time2code CLI

Each component page shows the command to add it:

<PackageManagerTabs className="not-typeset full-width" items={["button"]} />

The CLI needs no config file. It reads the import alias from your `tsconfig.json`, finds the CSS file that imports Tailwind CSS and installs the component's dependencies.

Components go to `components/ui`, `components/charts`, `components/marketing` and `hooks`, inside `src` if your alias points there. In a monorepo, the CLI asks which workspace to add them to.

### With the shadcn CLI

The components are also available as a [shadcn registry](https://ui.shadcn.com/docs/registry) under the `@time2code` namespace. Add the namespace to your `components.json`:

```json title="components.json"
{
  "registries": {
    "@time2code": "https://ui.time2code.dev/r/{name}.json"
  }
}
```

Then add components with the namespace:

<PackageManagerTabs
  className="not-typeset full-width"
  command="npx shadcn@latest add @time2code/button"
/>

To show shadcn CLI commands on every component page, select **shadcn** in the toggle above any install command.

### Manually

1. **Find a component** on the [UI Components](/docs/ui) or [Particles](/particles) pages.
2. **Copy the code** from the **Code** tab.
3. **Create a new file** in your project, such as `components/ui/button.tsx`, and paste the code.
4. **Install the dependencies** listed on the component's page.
5. **Import and use** the component in your app.

## Migrating From shadcn/ui or Radix UI

A step-by-step migration guide for projects built on shadcn/ui or Radix UI is planned. Until it's available, these are the differences you'll run into first:

- **`render` instead of `asChild`:** Base UI composes a part with another element through the `render` prop, as in `<DialogTrigger render={<Button>Open</Button>} />`.
- **`Popup` instead of `Content`:** The floating part of a component is called `DialogPopup`, `PopoverPopup` or `MenuPopup` rather than `DialogContent`.
- **Different color tokens:** Classes like `text-muted-foreground` or `bg-card` don't exist. See [Styling](/docs/styling#coming-from-shadcnui) for the equivalents.

## Working With AI

The documentation and the CLI are set up so AI coding assistants can use the components correctly:

- **MCP server:** The `time2code` CLI includes an MCP server with tools to list, search and view components, get usage examples and get the add command. To add it to your editor or agent, run `npx time2code mcp init` and choose Claude Code, Cursor, VS Code, OpenCode or Codex.
- **llms.txt:** The [llms.txt](/llms.txt) file maps the documentation for AI agents, and [llms-full.txt](/llms-full.txt) contains all of it.
- **Markdown pages:** Every page has a **Copy Markdown** button, so you can paste its content into a chat.
- **Agent Skills:** Run `npx skills add time2code0/ui` to teach your assistant time2code/ui's components, charts and patterns. See [Skills](/docs/skills).
