## Overview

The components are styled with a small set of color tokens. Each token is a Tailwind CSS theme variable, defined in an `@theme` block for light mode and overridden in a `.dark` block for dark mode.

Because the tokens live directly in the Tailwind theme, every token works as a utility class and as a CSS variable:

```tsx
<p className="text-foreground-muted">Changes are saved automatically.</p>
<div className="border bg-background-muted" />
<div style={{ color: "var(--color-foreground)" }} />
```

This differs from shadcn/ui, which defines variables like `--background` on `:root` and maps them into Tailwind with `@theme inline`. time2code/ui has no such mapping layer and uses fewer tokens. See [Coming From shadcn/ui](#coming-from-shadcnui) for the differences.

## Color Tokens

### Base

| Token | Used for |
| --- | --- |
| `background` | The page and raised surfaces, such as cards, popovers and dialogs |
| `background-muted` | Recessed surfaces, such as dialog footers and input group addons |
| `foreground` | Text and icons, and at low opacity, borders, rings and subtle fills |
| `foreground-muted` | Secondary text, such as descriptions, placeholders and labels |
| `accent` | Hover, highlighted and pressed states of menu items, buttons and options |
| `primary` | Your brand color, used sparingly, mostly by marketing components |
| `secondary` | A second brand color, used alongside `primary` |

UI components stay neutral: they're built from `background`, `foreground` and `accent`, and don't use `primary` or `secondary`. Instead of a separate border token, borders are `foreground` at 10% opacity. The stylesheet below sets that as the default border color for every element, so borders adapt to any surface in both modes.

### Status

Each status color comes in four tokens:

| Token | Used for |
| --- | --- |
| `destructive`, `info`, `success`, `warning` | Solid fills and icons |
| `*-foreground` | Text on a tinted surface, such as alert and badge text |
| `*-background` | Tinted surfaces, such as alerts and destructive menu items |
| `*-subtel` | Stronger tints, such as badges, alert frames and the focus ring of invalid fields |

For example, a destructive badge uses `bg-destructive-subtel text-destructive-foreground`.

### Charts

Charts read their series colors from `chart-1` to `chart-5`. Adding a chart adds these tokens to your stylesheet. See [Charts](/docs/charts).

## Installation

New projects created with `npx time2code create` already include the tokens. In an existing project, replace your global stylesheet, such as `app/globals.css`, with the following. If it already contains shadcn/ui variables, remove them, since the token names overlap.

The `@layer base` block sets the default border color and a thin scrollbar that matches the tokens.

## Customizing Colors

To change a color, edit its value in both the `@theme` block and the `.dark` block. Keep the lightness relationships between tokens, so that `foreground-muted` stays readable on `background` and the `*-subtel` tints stay visible next to their `*-background` tints.

To try palettes on this site, open the palette menu in the header, shown as colored dots next to the theme toggle. **Edit** changes the base and chart colors, and **Export** shows the CSS to paste into your stylesheet. It contains only the base and chart tokens, so your status colors stay as they are.

## Dark Mode

Dark mode is class-based. The line `@custom-variant dark (&:is(.dark *));` makes the `dark:` variant and the `.dark` overrides apply whenever an ancestor has the `dark` class. In Next.js, the `ThemeProvider` from the [root layout](/docs/get-started#set-up-the-root-layout) sets that class on `<html>`.

Most components need no `dark:` classes, because the tokens change with the mode. `primary` and `secondary` keep the same value in both modes unless you add them to the `.dark` block.

## Fonts

The components use two font variables:

- `--font-sans` for body text, buttons, labels and most UI elements, through the `font-sans` utility.
- `--font-mono` for code and other monospace text, through the `font-mono` utility.

The stylesheet above points them at `--font-geist-sans` and `--font-geist-mono`, the variables that `next/font` sets in the [root layout](/docs/get-started#set-up-the-root-layout), with system fallbacks.

### Custom Fonts

To use different fonts, load them with `next/font` and keep the variable names:

```tsx title="app/layout.tsx"
import { Inter, JetBrains_Mono } from "next/font/google";

const fontSans = Inter({
  display: "swap",
  subsets: ["latin"],
  variable: "--font-geist-sans",
});

const fontMono = JetBrains_Mono({
  display: "swap",
  subsets: ["latin"],
  variable: "--font-geist-mono",
});
```

To use your own variable names instead, update the `@theme inline` block to match. For example, with `variable: "--font-inter"`:

```css title="app/globals.css"
@theme inline {
  --font-sans: var(--font-inter), "Apple Color Emoji", "Segoe UI Emoji",
    "Segoe UI Symbol";
}
```

Apply the font variables to `<html>` and the `font-sans` class to `<body>`, so both cascade to every element, including portaled popups.

## Coming From shadcn/ui

If you've used shadcn/ui, these are the equivalents of its tokens:

| shadcn/ui | time2code/ui |
| --- | --- |
| `bg-card`, `bg-popover` | `bg-background` |
| `bg-muted` | `bg-background-muted` |
| `text-muted-foreground` | `text-foreground-muted` |
| `bg-primary`, `text-primary-foreground` | `bg-foreground`, `text-background` |
| `border-border`, `border-input` | `border-foreground/10` |
| `ring-ring` | `ring-foreground` |
| `var(--foreground)` | `var(--color-foreground)` |

shadcn/ui's `primary` is the dark, neutral color of default buttons. In time2code/ui, that role is `foreground`, and `primary` is free for your brand color.
